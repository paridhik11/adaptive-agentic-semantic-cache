# R4 bounded documentation-agent closeout

Date: 2026-10-18 (Asia/Calcutta). Engineering integration passes the checks below.
Answer correctness, semantic precision, memory benefit and live utility remain
unmeasured. Historical Gate A remains failed. This phase does not repair its
spent evaluation or justify a performance claim.

## Delivered

- DocumentAgent as a client of the existing GatewayService; no replacement cache.
- Strict bounded model plan, ordered dependencies, allowlisted actual local
  document search/read, draft and model review with one bounded feedback revision.
- SQLite stage checkpoints, durable call reservations, per-stage work/usage trace,
  source-content hashing, tenant/principal isolation and scoped completed-task memory.
- Human approve/modify/reject after process restart; terminal resume does not rerun
  completed model/tool work. Task deletion and scoped memory invalidation.
- CLI fixture/live-gateway modes, explicit cache switch, authored demo corpus and
  separate-process reproducible functional smoke.

See `../document_agent.md` for commands and detailed contracts.

## Evidence and interpretation

`R4_FUNCTIONAL_SMOKE.json` is generated by `scripts/smoke_document_agent.py`.
It executes independent CLI processes against one SQLite database: plan, search,
read, draft, review, pause, approve and resume; a second task is rejected.
The first task makes three simulated provider calls and two document-tool calls.
External model calls and independent answer reviews are both zero. Scripted
fixture answers and approval prove wiring, not task correctness.

Focused tests cover schema rejection, actual tool dispatch, missing source,
review retry/task budget, durable reservations, source revision and principal
isolation, concurrent runners, restart approval, modify/reject, memory deletion,
provider errors and exact draft reuse. A controlled repeated-task test produces
three then two fixture calls: only drafting is reused; planning/review still run.
This is a functional accounting assertion, not representative savings.
Final regression counts and source hashes are recorded in `R4_VALIDATION.json`.

## Limits and explicit deviations

The accepted bounded agent is implemented, not the entire Project 15 platform.
Plans are static: search outcomes enter evidence but do not dynamically rewrite
subsequent arguments. No arbitrary external writes or tool side effects exist.
Review is fallible. Human workflow approval is not independent evaluation.
The demo corpus is authored; pinned real-source task evaluation is R5 work.
No live provider/model validation was performed and no paid inference was used.

Agent guarded-semantic mode is rejected until verifier reservations are integrated
with the task budget. Exact/shadow work and bypass remain supported. The live CLI
conservatively bypasses cache for contextual agent prompts; it requires a separately
quota-enforced gateway, with optional environment bearer authentication. Task
budgets alone do not enforce the project's daily free-provider quota.

Crash after inference but before checkpoint can repeat that inference; each retry
consumes a durable reservation. Unknown provider failure counts remain unknown.
A competing runner may consume a reservation without work; budgets are conservative.
SQLite writes are serialized, including model execution, so this is not a throughput
or distributed-worker result. No tool memoization, memory-benefit result, automatic
retention policy or streaming-cache support is claimed. Task deletion does not
purge gateway cache entries; use gateway retention/invalidation separately.
