# Local exact-cache latency pilot

Use the first eight holdout seed prompts in the committed risk fixture order. Compare one fresh Qwen generation with warm exact reuse for the same request. One excluded warm-up runs on the first calibration prompt. Prime an in-memory exact cache once per measured prompt outside the timed trials. Alternate the order of fresh and cached trials by prompt index. Time the cache boundary through response return, including all tokenization and generation on the fresh path. Measure eight paired observations and record SHA-256 answer equality, local generation calls, generated completion tokens, and p50 latency. Report priming separately as work required before a hit. Keep responses out of the receipts. The comparison is a CPU component measurement on literal repeats and excludes multi-step agent execution, semantic hits, network latency, and real charges.

Use Qwen/Qwen2.5-0.5B-Instruct at revision 7ae557604adf67be50417f59c2c2f167def9a775, CPU FP32, two torch threads, greedy decode and at most 32 new tokens. Model cache must be populated with that revision before running. The model is loaded before timing. There is no online provider call.
