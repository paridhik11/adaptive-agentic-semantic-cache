Executive Summary

Standard semantic caching systems for LLM architectures rely naively on dense embedding similarity thresholds (e.g., cosine similarity > 0.85). In high-throughput production environments, this naive mechanism fails catastrophically due to two distinct failure modes:

  1. Temporal Staleness & Volatility Hazards: Queries requesting volatile, live, or time-sensitive data (e.g., live stock prices, current weather, active leadership, changing software versions) are matched to previously cached answers, serving stale hallucinations to users.
  2. Subtle Intent & Contextual Traps: Queries that are close in vector space but differ in critical negative scope, syntax versions, or constraints are falsely reused.

The Adaptive Agentic Semantic Cache solves this with a multi-layered defense pipeline. Phase 0 and Phase 1.1 are now 100% complete. The stability classification subsystem achieves zero dangerous errors (0.00%) in 5-fold stratified cross-validation while executing in sub-millisecond time.

Section 2: Phase 0 Foundations & Mathematical Metrics

2.1 The 6-Class Reuse Taxonomy

  • SAFE_EQUIVALENT: Semantically and functionally identical queries. Cache hit is safe and verified.
  • UNSAFE_DIFFERENT_INTENT: Queries share words but diverge in execution goal.
  • UNSAFE_SCOPE_MISMATCH: Scope mismatch (e.g., Python 2 vs Python 3, single file vs recursive).
  • UNSAFE_CONTEXT_MISMATCH: Implicit operational assumptions differ (e.g., Windows vs Linux paths).
  • UNSAFE_DYNAMIC_TEMPORAL: Volatile state requiring real-time primary model generation.
  • UNSAFE_DIFFERENT_TOPIC: High embedding similarity between entirely distinct domain topics.

2.2 Core Mathematical Metrics Defined in docs/evaluation_metrics.md

Metric Name Symbol Formula Operational Meaning
Candidate Retrieval Rate $ ext{CRR}_{ ext{retrieval}}$ $N_{ ext{retrieved}} / N$ Proportion of queries finding a candidate in cache vector index
Actual Reuse Rate $ ext{ARR}$ $(TP + FP) / N$ Actual percentage of user requests served from cache
Correct Reuse Rate (Precision) $ ext{CRR}$ $TP / (TP + FP)$ Proportion of served cached responses that were genuinely safe
Cache Hazard / Poisoning Rate $ ext{IRR}_{ ext{cache}}$ $FP / (TP + FP)$ Critical Safety Metric: Stale/incorrect answers served (Goal: 0.0)
False Rejection Rate $ ext{FRR}$ $FN / (TP + FN)$ Opportunity cost: Safely reusable queries unnecessarily regenerated

Section 3: Phase 1.0 Failure Mode & Phase 1.1 Remediation

🚨 Phase 1.0 Critical Failure Mode Discovered
During initial testing against the 85-query Human Credibility Audit corpus, Phase 1.0 exhibited a 57.41% Dangerous Error Rate (31 dynamic queries misclassified as STABLE). Queries such as "current prime minister of UK", "latest version of Python", and "gas prices near me" bypassed rules and were marked cacheable by the optimistic fallback prior.

Phase 1.1 Four-Stage Engineering Fixes:

  • Sub-stage A (Conservative Bias Override): Enforced STABLE_CONFIDENCE_THRESHOLD = 0.80. Uncertain predictions default to DYNAMIC (bypass). Reduced errors from 31 to 3.
  • Sub-stage B (Role Partitioning): Formally separated dev corpora from pristine heldout and final test sets.
  • Sub-stage C (Answer-Type Taxonomy & Anchoring): Added 7 volatility patterns and completed temporal anchor parsing (e.g., past years protect queries as STABLE). Rule resolution jumped to 44.7%.
  • Sub-stage D (Trained Lexical Fallback): Implemented word/character n-gram TF-IDF + balanced Logistic Regression. Reduced dangerous errors to 0.00% (0 / 102).
