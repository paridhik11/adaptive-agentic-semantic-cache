# Paired mixed-request local timing protocol

Replay 24 requests from the first six V3 holdout intents in committed order. Select the literal repeat, first paraphrase, changed reporting month and unresolved request from every intent. This is a timing replay of spent fixtures. Use one seed per intent and one excluded warm-up from calibration. Compare forced fresh generation with the V3 context arm using the same trusted request headers for each pair. Alternate within-pair order. Time both arms through return, including any retrieval, verification, exact lookup and CPU generation. Measure seed admission as separate once-per-intent cost. The seed is a fixed authored answer. Its cache preparation time excludes the cost of producing that answer.

Use the same pinned local Qwen2.5-0.5B-Instruct revision as the exact pilot, CPU FP32, two threads, greedy generation and at most 32 new tokens. Load the same pinned MiniLM models as the V3 comparison. All misses perform real local generation with no network transport. Prevent those generated probes from becoming reusable seeds. Verify every served seed's identity and expected eligibility. Fresh generations on the same pair may be checked for identical generated bytes when both arms miss, but their factual quality is outside the timing pilot.

Report summed elapsed time and median per-request latency for both arms, time including cache preparation, actual generation calls, actual completion tokens, split by request scenario, and platform details. No extrapolation to production latency, token billing, concurrent throughput or new data.
